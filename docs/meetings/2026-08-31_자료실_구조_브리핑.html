자료가 올라가는 흐름

제안누구나 자료 등록방문자든 운영진이든 같은 폼. URL 또는 파일(10MB). 제출 시 중복 자동 확인
대기등록요청에 쌓임운영진에게 알림 메일. 승인 전에 제목·설명·분류·태그를 다듬을 수 있음
승인운영진 2명서로 다른 두 사람이 확인. 관리자는 사유를 적고 단독 승인 가능(예외)
게시사이트에 공개제안자에게 승인 메일. 파일 자료는 이 시점에 드라이브로 이동
원칙은 2인 승인. 한 사람이 놓치기 쉬운 중복·품질·적합성을 두 번 거르기 위해서입니다. 관리 화면에 따로 "자료 추가" 버튼은 없고, 운영진도 같은 폼으로 제안해 승인을 거칩니다.

파일은 맥비님 드라이브에 연결 진행 중

맥비님 요청(자료를 한 곳에, 드라이브 4TB 여유)에 맞춰 업로드 파일의 최종 저장소를 맥비님 구글 드라이브로 정했습니다.

저장 시점승인이 끝나는 순간 자동 이동. 대기 중에는 사이트 임시 저장소, 반려 파일은 드라이브에 들어가지 않음
파일명운영진이 정리한 제목으로 저장 (올린 사람의 원래 파일명이 아님)
공유 범위파일별 "링크가 있는 사람은 보기". 폴더 전체 공개 아님. 연결 스크립트는 자기가 만든 폴더 밖에는 접근 불가
실패 시운영진에게 메일, 자료는 임시 링크로 계속 다운로드. 자료 관리의 "드라이브로" 버튼으로 재시도
왜 이 방식인가개인 드라이브에는 봇(서비스 계정)이 파일을 저장할 수 없어, 맥비님 계정에서 실행되는 작은 스크립트가 받아 저장하는 구조. 맥비님이 한 번만 설정하면 이후 수정은 운영 쪽에서 처리
남은 일맥비님 설정 완료 → 연결 테스트 → 기존 파일 20건 이관
