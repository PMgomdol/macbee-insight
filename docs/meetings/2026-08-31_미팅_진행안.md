## 3. 안건 A. 등록 방식 — 2인 승인을 누구에게 적용할지

먼저 현상을 사실로 짚어줌: 시트 때는 맥비님이 붙여넣으면 끝이었는데, 지금은 한 건씩 폼 입력 → AI 분석 → 다른 운영진 승인 대기. 등록의 대부분을 하는 맥비님에게 병목이 생겼음.

**질문 (결정 전에 반드시 들을 것)**

- 맥비님: 링크를 평소 어디에 어떻게 모으시나요? (톡방 / 북마크 / 시트)
  - 💡 일괄 등록 기능을 어떤 형태로 만들지의 설계 근거. 답이 "시트"면 시트 일괄 등록, "읽다가 바로"면 북마클릿 우선
- 전원: 운영진이 올린 자료를 사전 검수 없이 공개해도 되는가? 우려가 있다면 구체적으로 무엇인가?
  - 💡 5/7 회의에서 "운영자 2명 승인"을 정한 건 멤버 오픈 전제였음 — 운영진 자신에게도 적용할지는 그때 논의 안 된 지점이라는 걸 짚어주면 부담 없이 바꿀 수 있음

**선택지 (질문 답 듣고 제시)**

1. 운영진 등록 즉시 게시 + 사후 검수 (추천 — 숨김·복구로 언제든 되돌림)
2. 운영진 등록은 1인 승인만 (본인 외 1명)
3. 지금 그대로 2인

**부수 결정**: 제안자 본인이 자기 제안을 승인하는 것 허용할지. 지금은 허용됨 — 개인정보보호포털 건이 실제 사례.

**결정되면 말할 것**: 1안은 반나절 작업으로 이번 주 반영. 이어서 여러 URL 일괄 등록 → 읽던 페이지에서 바로 등록 순서로 만들겠다.

- ⚠️ 결정을 유도하되 밀어붙이지 않음. 우려가 강하면 "2안으로 시작해서 한 달 뒤 재검토"로 후퇴선을 잡음.

## 4. 안건 B. 오픈 시점·방식

맥비님이 8/26에 "파일 등록만 확인되면 베타 오픈해보자"고 제안하셨던 것을 상기시킴. 그리고 그 조건이 충족됐음을 알림 — 파일 등록 오류 수정 완료, 드라이브 연결·실제 승인까지 테스트 통과. **베타 오픈을 막는 기술 요인은 없음.**

**정할 것 (순서대로)**

1. 베타 오픈 날짜 — 이번 주 중 어느 날로?
2. 베타 범위 — 톡방 공지만? 검색 노출(구글 등)은 계속 차단할지, 함께 열지
   - 💡 추천: 베타는 톡방만, 검색 노출은 정식 오픈 때. 되돌리기 어려운 건 마지막에
3. 의견 수집 창구 — 사이트 "의견 보내기"(VOC) 하나로 모을지, 톡방 병행할지
4. 정식 오픈 기준 — 무엇이 확인되면 "정식"인가 (예: 2주간 큰 오류 없음)

**오픈 시 할 일 (안재찬, 공유만)**: 검색 차단 해제 + 서치콘솔 삭제요청 취소 + 톡방 공지문.

## 5. 안건 C. 담당 나눔

가이드 17번 표의 여섯 영역을 화면에 띄우고 채움: 등록요청 검수 / 자료 관리·정리 / 의견(VOC) 답변 / 카테고리·태그 정리 / 대시보드·지표 확인 / 새 자료 발굴·수집.

- 사람별 배정이 아니라 **"주 담당 1 + 백업 1"**로 잡음.
- 💡 검수 부담은 안건 A 결과에 따라 달라지므로 반드시 A 다음에 정함 (1안이면 검수량이 크게 줆).
- 💡 5/7 회의의 교훈 — "전원이 주 20개" 같은 균등 분담은 흐지부지됐음. 이번엔 영역별 주인을 정하는 방식이라는 걸 언급해도 좋음.
- 정해지면 그 자리에서 가이드 17번 표에 기록함(안재찬).

## 6. 안건 D. 운영 시트 폐기 여부

현상을 먼저 사실로 짚어줌: 운영 시트("맥비기획_자료실_DB")는 매일 새벽 5시 사이트 DB가 자동 복사되는 읽기 전용 사본. 작업 도구가 아니며, 시트를 고쳐도 사이트에 반영되지 않음. 나머지 탭들은 이관 당시 작업 흔적.

**질문 (결정 전에 들을 것)**

- 전원: 요즘도 시트를 열어보는 사람이 있는지, 있다면 어떤 용도인지
  - 💡 답이 "안 본다"면 폐기 쪽 근거, "훑어볼 때 쓴다"면 유지 쪽 근거가 됨

**선택지**

1. 새벽 복사 중단 + 시트는 "보관용" 표시만 남기고 닫음 (폐기)
2. 지금처럼 유지 (열람·비상 대조용 사본)

- 💡 폐기하면 얻는 것: "시트 고치면 반영된다"는 오해의 소지 제거, 관리 대상 하나 축소. 유지하면 얻는 것: 익숙한 화면으로 훑어보기, 사이트 장애 시 대조 수단.
- 💡 과거 삭제분 97건이 시트 경유로 재유입된 사고가 있었음 — 시트가 살아 있는 한 "시트 = 원본"으로 착각할 통로가 남는다는 점을 근거로 쓸 수 있음.

**결정되면 말할 것**: 폐기로 정해지면 새벽 복사를 멈추고 시트 첫 탭에 "보관용 — 최신 자료는 사이트" 안내를 남김. 원본 톡방 시트는 이번 논의와 무관하게 기록 보관.

## 7. 전달할 정보

### 파일 저장 — 맥비님 드라이브 연결 완료
- 오늘부터 승인되는 파일은 자동으로 맥비님 드라이브 "맥비기획 자료실 (자료실 업로드)" 폴더에 저장됨. 실제 승인 테스트까지 통과함.
- 업로드 한도는 30MB. 근거: 전송 구조상 1회 한계가 약 35MB(실측), 지금까지 가장 큰 파일이 면접 질문 시리즈 20.4MB라 여유 있음.
- 기존 파일 20건은 이관할 필요 없음 — 확인해보니 시트 시절부터 전부 맥비님 드라이브 링크였음.
- 테스트 파일 4개가 폴더에 남아 있음 — 맥비님이 지워주시면 됨.

### 계정 명의
- 도메인·서버·DB 대부분 안재찬 개인 계정(asa067714) 명의. 장기적으로 공동 접근·이전 논의가 필요함 — 오늘은 인지만, 결정은 다음에.

## 주의

- 설명이 길어지면 결정 시간을 잃음 — 구조 설명은 10분 안에 끊고, 세부 질문은 "가이드에 있음 + 따로 안내"로 넘김.
- A안(즉시 게시)을 추천하되 강요하지 않음. 반대가 강하면 후퇴선(1인 승인 → 한 달 뒤 재검토)으로.
- 검색 노출 해제는 되돌리기 번거로움 — 베타 단계에서 성급히 열지 않도록 잡아줌.
- 계정 명의 건은 오늘 결론 내려 하지 않음. "인지 + 다음 안건"까지만.
- 결정 없이 넘어간 안건은 "누가·언제까지 정할지"라도 확정하고 끝냄.
