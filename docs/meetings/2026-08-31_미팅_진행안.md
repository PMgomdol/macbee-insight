## 3. 안건 A. 등록·승인 방식

앞으로 자료 등록과 승인을 어떻게 진행할지 정하는 자리.

**배경**
- 지금은 누가 올리든 같은 폼으로 제안하고, 다른 운영진 2명이 승인해야 게시됨.
- 시트 때는 맥비님이 붙여넣으면 끝이었음. 등록을 가장 많이 하는 맥비님에게 병목이 생김.

**결정할 것 ① — 운영진이 등록하는 자료, 승인을 몇 명 거칠지**
- 문제: 운영진이 올려도 다른 운영진 2명의 승인이 필요함. 자료 1건에 세 사람이 붙는 셈이라 번거로움.
- 제안(재찬): 운영진이 올린 자료는 **다른 운영진 1명 확인이면 게시**. 급하거나 명백한 자료는 운영진 재량으로 단독 승인도 허용.
- 다른 선택지: 운영진 등록은 즉시 게시하고 사후 검수 / 지금처럼 2명 유지.
- 함께 정할 것: 본인이 올린 자료를 본인이 승인하는 것을 허용할지. 지금은 막혀 있지 않음(개인정보보호포털 건이 실제 사례).
- 💡 5/7 회의에서 "2명 승인"을 정한 건 멤버에게 등록을 열 때를 대비한 것. 운영진 자신에게도 똑같이 적용할지는 그때 논의된 적 없음 — 이걸 짚어주면 부담 없이 바꿀 수 있음.

**결정할 것 ② — 맥비님의 등록 방식**
- 우려: 시트에 자유롭게 올리시던 것에 비해 폼 입력과 승인 대기가 오히려 번거로울 수 있음. 파일 30MB 제한도 새로 생김.
- 제안(재찬): 맥비님은 지금처럼 **드라이브에 직접 올리고, 그 링크를 등록**. 드라이브 링크를 등록하면 자동으로 "파일 자료"로 분류되게 고쳐둘 수 있음(간단한 작업). 이러면 용량 제한도 없고 익숙한 방식 그대로임.
- 맥비님께 여쭤볼 것:
  - 직접 등록해보니 어려운 점이 있으셨는지
  - 올릴 링크를 평소 어디에 모아두시는지 (톡방 / 북마크 / 시트) — 일괄 등록 기능을 만들 때 참고

**결정되면**
- ①은 이번 주 반영(반나절 작업). ②의 자동 분류도 함께.
- 이어서 여러 URL 일괄 등록 → 읽던 페이지에서 바로 등록 순서로 개선 예정.

- ⚠️ 결정을 유도하되 밀어붙이지 않음. 의견이 갈리면 "한 달 해보고 재검토"로 기한을 정해 마무리.

## 4. 안건 B. 베타 오픈 시점·방식

언제, 어떤 범위로 사이트를 열지 정하는 자리.

**배경**
- 맥비님 제안(8/26): 파일 등록만 확인되면 베타로 열고 이용자 의견을 받아보자.
- 그 조건은 충족됨. 파일 등록 오류를 고쳤고, 드라이브 저장까지 실제 승인으로 확인함. 기술적으로 오픈을 막는 것은 없음.

**결정할 것 ① — 베타 오픈 날짜**
- 이번 주 중 언제로 할지.

**결정할 것 ② — 공개 범위**
- 베타 동안 톡방 공지만 할지, 구글 검색 노출까지 열지.
- 제안(재찬): 베타는 톡방 공지만. 검색 노출은 한번 열면 되돌리기 번거로우니 정식 오픈 때 함께.

**결정할 것 ③ — 의견 받는 창구**
- 사이트의 "의견 보내기" 하나로 모을지, 톡방 의견도 병행해서 받을지.

**결정할 것 ④ — 정식 오픈 기준**
- 무엇이 확인되면 정식으로 전환할지. 예: 2주간 큰 오류 없으면.

**결정되면**
- 오픈 당일 할 일(재찬): 검색 차단 해제, 서치콘솔 삭제요청 취소, 톡방 공지문. 이건 공유만 하면 됨.

## 5. 안건 C. 담당 나눔

운영 일 여섯 가지에 각각 담당을 정하는 자리.

**배경**
- 지금은 담당 구분이 없음. 일은 여섯 가지인데 누가 뭘 보는지 정한 적이 없음.
- 여섯 영역: 등록요청 검수 / 자료 관리·정리 / 의견(VOC) 답변 / 카테고리·태그 정리 / 대시보드·지표 확인 / 새 자료 발굴·수집.

**결정할 것 — 영역마다 주 담당 1명 + 백업 1명**
- 진행 방법: 운영 가이드 17번 표를 화면에 띄우고 그 자리에서 채움.
- 운영진을 더 초대할지도 함께 정함. 초대는 관리 화면 "운영진 초대"에서 가능.
- 💡 검수 담당은 안건 A 결과에 따라 부담이 크게 달라짐 — 그래서 A 다음 순서로 잡은 것.
- 💡 5/7 회의의 "전원이 주 20개" 같은 균등 분담은 흐지부지됐음. 이번엔 영역별로 주인을 정하는 방식이라고 짚어주면 좋음.

**결정되면**
- 그 자리에서 가이드 17번 표에 기록함(재찬).

## 6. 안건 D. 운영 시트 폐기 여부

예전 구글 시트를 계속 둘지, 정리할지 정하는 자리.

**배경**
- 운영 시트("맥비기획_자료실_DB")는 이제 작업 도구가 아님. 매일 새벽 5시에 사이트 DB가 자동 복사되는 읽기 전용 사본임.
- 시트를 고쳐도 사이트에 반영되지 않음. 나머지 탭들은 이관 때 쓰던 작업 흔적.

**먼저 물어볼 것**
- 요즘도 시트를 열어보는 분이 있는지, 있다면 어떤 용도인지.
- 💡 "안 본다"면 폐기 쪽, "훑어볼 때 쓴다"면 유지 쪽 근거가 됨.

**결정할 것 — 둘 중 하나**
1. 폐기: 새벽 복사를 멈추고, 시트에는 "보관용" 표시만 남김.
2. 유지: 지금처럼 둠. 훑어보기·비상시 대조용.

**판단 재료**
- 폐기하면: "시트를 고치면 반영된다"는 오해가 사라짐. 실제로 삭제한 자료 97건이 시트를 거쳐 되살아난 사고가 있었음.
- 유지하면: 익숙한 화면으로 자료를 훑어볼 수 있고, 사이트에 문제가 생겼을 때 대조 수단이 됨.

**결정되면**
- 폐기로 정해지면(재찬): 새벽 복사 중단, 시트 첫 탭에 "보관용 — 최신 자료는 사이트" 안내.
- 톡방 원본 시트는 이번 논의와 무관하게 그대로 보관.

## 7. 자료 검수 현황 — 삭제 검토 마무리

이관 때 삭제했던 자료들의 재검토가 어떻게 끝났는지 공유하는 자리. 맥비님이 검토해주신 결과가 어떻게 반영됐는지 직접 확인받는 것이 목적.

1. 이관하며 삭제한 자료들의 사유 대장을 만듦 (8/13, 자동 생성)

## 8. 전달할 정보

### 파일 저장 — 맥비님 드라이브 연결 완료
- 오늘부터 승인되는 파일은 자동으로 맥비님 드라이브 "맥비기획 자료실 (자료실 업로드)" 폴더에 저장됨. 실제 승인 테스트까지 통과함.
- 업로드 한도는 30MB. 근거: 전송 구조상 1회 한계가 약 35MB(실측), 지금까지 가장 큰 파일이 면접 질문 시리즈 20.4MB라 여유 있음.
- 기존 파일 20건은 이관할 필요 없음 — 확인해보니 시트 시절부터 전부 맥비님 드라이브 링크였음.
- 테스트 파일 4개가 폴더에 남아 있음 — 맥비님이 지워주시면 됨.

### 계정 명의
- 도메인·서버·DB 대부분 안재찬 개인 계정(asa067714) 명의. 장기적으로 공동 접근·이전 논의가 필요함 — 오늘은 인지만, 결정은 다음에.

### 최근 변경
- 운영 가이드 완성, 속도 개선(서울 서버), 관리자 단독 승인(사유 기록 필수), 검색창 통일 등 — 관리 화면 "업데이트 내역"에서 확인 가능.

| 사이트가 느려요 | 서울 서버 이전으로 개선됨. 여전히 느린 화면 있으면 알려달라 |
| 비용은? | 현재 무료 구간 (도메인 1년 결제만). 용량·트래픽은 대시보드에서 관찰 중 |

## 주의

- 설명이 길어지면 결정 시간을 잃음 — 구조 설명은 10분 안에 끊고, 세부 질문은 "가이드에 있음 + 따로 안내"로 넘김.
- A안(즉시 게시)을 추천하되 강요하지 않음. 반대가 강하면 후퇴선(1인 승인 → 한 달 뒤 재검토)으로.
- 검색 노출 해제는 되돌리기 번거로움 — 베타 단계에서 성급히 열지 않도록 잡아줌.
- 계정 명의 건은 오늘 결론 내려 하지 않음. "인지 + 다음 안건"까지만.
- 결정 없이 넘어간 안건은 "누가·언제까지 정할지"라도 확정하고 끝냄.
