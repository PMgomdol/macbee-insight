# 맥비 자료실 UX Writing 가이드

정립일: 2026-08-10 · 기준: 토스 라이팅 원칙 + Atlassian DS 시각 제약
적용 범위: 자료실 웹(`web/`)의 모든 사용자 노출 문구 — 버튼·라벨·빈 상태·에러·안내·placeholder·aria-label

> 새 문구를 쓰거나 고칠 때 이 문서를 정본으로 삼는다. 판단이 애매하면 §9 체크리스트로 검수한다.

---

## 1. 원칙 (토스 라이팅 5)

1. **사용자 입장에서 쓴다.** 시스템 관점("자료가 없습니다")이 아니라 사용자 관점("찾으시는 자료가 아직 없어요")으로.
2. **쉬운 말을 쓴다.** 영어·한자어·전문용어를 줄인다. "동기화 실패" → "불러오지 못했어요".
3. **짧게, 하나의 메시지.** 한 화면에 한 초점. 문장을 자른다. 접속사로 늘어뜨리지 않는다.
4. **사용자를 탓하지 않는다.** "잘못 입력하셨습니다" → "이메일 주소를 확인해주세요". 실패의 주어는 시스템이거나 없다.
5. **정직하게.** 과장·불안 조성 없이. 실제로 일어나는 일만 말한다.

이 다섯이 나머지 모든 규칙보다 우선한다.

---

## 2. 문체

- **해요체로 고정한다.** 합니다체·개조식 서술을 섞지 않는다.
  - ✅ "실제 트래픽이 쌓이면 그래프가 채워져요"
  - ❌ "실제 트래픽이 쌓여야 그래프가 채워집니다"
- **반말 금지.** 예외 없음.
- **띄어쓰기: 보조용언은 붙여 쓴다.** `~해주세요`로 통일 (원칙상 띄어쓰기도 맞지만 하나로 고정).
  - ✅ 확인해주세요 · 다시 시도해주세요 · 적어주세요
  - ❌ 확인해 주세요 · 다시 시도해 주세요
- **감정 과잉 금지.** 시스템 메시지는 해요체라도 감정을 빼고 사실만.
  - ✅ "권한이 없어요" · ❌ "앗, 접근할 수 없네요"
- **시스템은 헤매지 않는다.** "모르겠어요"류 금지 — 시스템이 멍청해 보인다.
  - ✅ "상태를 불러오지 못했어요" · ❌ "상태를 모르겠어요"

---

## 3. 버튼·CTA

### 위계별 문체

| 위계 | 문체 | 예시 |
|---|---|---|
| **주 액션** (Primary) | 동사형 `~하기` | 등록하기 · 저장하기 · 보내기 · 자료 검색하기 · 다시 시도하기 |
| **보조 액션** (Secondary) | 짧은 동사/명사 | 취소 · 닫기 · 접기 · 홈으로 |
| **조밀 반복 UI** (운영진 테이블 등) | 명사 허용 | 승인 · 단독 승인 · 거절 |

### 규칙

- **화자형 `~할게요`·`~할래요`는 버튼에 쓰지 않는다.** 토스트·상태·확인 다이얼로그 본문에만 (시스템이 방금 한 일을 말할 때). 예: 토스트 "승인했어요", 다이얼로그 "거절할게요. 계속할까요?"
- **"확인" 남발 금지.** 무엇을 하는 버튼인지 동사로 드러낸다. 저장·삭제·보내기.
- **한 화면에 주 액션은 하나.** 강조 버튼이 둘 이상이면 위계를 다시 본다.

---

## 4. 에러 메시지 공식

```
[무엇이 안 됐는지 (탓 없이)] + [다음에 뭘 하면 되는지]
```

- 사용자를 주어로 한 비난 금지. 실패 주어는 시스템이거나 생략.
- 가능하면 다음 행동을 준다. 행동이 없으면 "잠시 후 다시 시도해주세요".
- 기술 용어·에러코드는 사용자 문구에 노출하지 않는다. (운영진 알림용은 예외)

| ✅ | ❌ |
|---|---|
| 이메일 주소를 확인해주세요 | 이메일 형식이 이상해요 |
| 파일을 올리지 못했어요. 잠시 후 다시 시도해주세요 | 업로드 실패 (500) |
| 50MB까지 올릴 수 있어요. 파일을 줄이거나 Drive 링크로 등록해보세요 | 용량 초과 |

---

## 5. 빈 상태 공식

```
[왜 비었는지] + [사용자가 할 수 있는 대안]
```

- ✅ "이 필터 조합에는 자료가 없어요. 필터를 초기화해보세요."
- ✅ "찾는 자료가 커뮤니티에 아직 없나 봐요. 이 주제 자료를 제안해보세요."
- ❌ "결과 없음" / "데이터가 존재하지 않습니다"

---

## 6. 용어·표현 표준

### 봉사동사 절제

`~해드려요`(채워드려요·정리해드려요·보여드려요)는 반복되면 굽신거리고 AI가 쓴 티가 난다. **중립 동사로 바꾼다.**

| 절제 | 원래 |
|---|---|
| 자동으로 채워져요 | 알아서 채워드려요 |
| 자동으로 정리돼요 | 알아서 정리해드려요 |
| 보여줘요 | 보여드려요 |

**예외:** 결과 통보처럼 사용자에게 정말 봉사하는 1~2 지점만 서비스톤 허용. 예: "검토 결과는 이메일로 알려드릴게요."

### 표준 단어

| 표준 | 지양 |
|---|---|
| 불러오다 | 동기화·로드·fetch |
| 올리다 / 업로드 | (업로드는 통용어라 허용) |
| 자료 | 콘텐츠·리소스·아이템 |
| 운영진 | 관리자·admin (역할 구분 필요할 때만 관리자) |

### 중복 문구 정본

같은 뜻은 하나로 통일한다. **단, 의미가 다르면 통일하지 않는다** — "승인"과 "거절/처리"는 다른 동작이므로 하나로 뭉개면 오표기.

- **본인 신청 안내** → 접미사 `~할 수 있어요`를 떼고 간결하게. 동작 의미는 보존:
  - 승인 맥락 → `본인 신청은 다른 운영진이 승인해요.`
  - 거절·범용 맥락 → `본인 신청은 다른 운영진이 처리해요.`
- **전송 완료** → `잘 보냈어요` (문구 자체는 유지, 화면마다 다르게 쓰지 말 것)

---

## 7. 숫자·기호

- **숫자는 아라비아 숫자.** "세 건" ❌ → "3건" ✅
- **가운뎃점 `·`** = 나열/메타 구분 전용. "제목·태그·카테고리", "이름 · 운영진".
- **엠대시 `—`** = 에러 상세 앞. "등록하지 못했어요 — {사유}". 장식용 헤딩엔 남용 금지.
- **화살표 `→ ↳`** = 이동/파생 표시 최소 사용. 이모지로 대체 금지 (§8).

---

## 8. 시각·이모지

- **이모지 금지.** Atlassian DS 원칙. 강조는 텍스트 위계·색(accent 1색)으로.
- 문구는 텍스트만으로 톤을 낸다. 토스는 이모지를 쓰지만 우리는 안 쓴다 — 여기서만 갈라진다.

---

## 9. aria-label 문투

- 화면 낭독용도 해요체·간결하게. 동작이면 동사, 대상이면 명사구.
  - "검색 지우기", "메뉴 열기", "다음 배너로 이동", "{제목} 내 검색"
- 시각 라벨과 중복 낭독되지 않게 한다. 아이콘 전용 버튼에만 붙인다.

---

## 10. 신규 문구 셀프 체크리스트

새 문구 넣기 전 10초 검수:

- [ ] 해요체인가? 합니다체·반말 섞이지 않았나?
- [ ] 사용자 입장인가? (시스템 관점 아님)
- [ ] 사용자를 탓하지 않나?
- [ ] 더 짧게 못 자르나? 한 초점인가?
- [ ] 버튼이면 §3 위계 문체에 맞나? (`~할게요` 아님)
- [ ] 에러면 "다음 행동"이 있나?
- [ ] 쉬운 말인가? 전문용어·영어 뺐나?
- [ ] `~해드려요` 반복 아닌가?
- [ ] 숫자 아라비아, 기호 §7 맞나? 이모지 없나?
- [ ] 같은 뜻 문구가 이미 있나? (정본 재사용)
